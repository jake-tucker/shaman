# Begin a scheduled Compaction ahead of a Prompt Cache lapse

A Provider keeps a Session's context in a Prompt Cache for a Cache Lifetime of idleness; once it lapses, the next Prompt re-reads the whole context at fresh prices, which on a large context costs dollars. We decided that Suru may, behind an Experimental Setting that is off by default, begin a Compaction of its own two minutes before the lapse, so the summary is made while the context is still cheap to read and the Session goes cold small rather than large. It is a third kind of Compaction, **scheduled**, beside the automatic and manual kinds ADR 0041 distinguished, and it begins a Turn of its own exactly as a manual one does.

Suru spends the user's money here without being asked in the moment, so the decision is bounded on every side. It fires only where the Lapse Penalty reaches a Setting's dollar threshold, because the penalty is the one quantity the Compaction exists to save and it scales across Models where a token count does not. A second Setting keeps it to Sessions that are not Settled unless the user widens it to all. It fires at most once for each idle stretch and is never tried again after failing. It fires only on an idle top-level Session or Subsession: never a Subagent, whose context dies with its work, and never a Session that is Working, Monitoring, or has Subagents working beneath it when the moment arrives, which is skipped rather than deferred. A Provider that declares no Cache Lifetime has no lapse to get ahead of, so its Sessions are never compacted this way.

The bounds are drawn from the Prompt Cache itself. An idle stretch is owed a scheduled Compaction only where the Turn that began it wrote the cache, setting the lapse moment the Compaction gets ahead of: a Turn that wrote nothing, stopped or failing before any call, leaves the cache and its moment as they were, so the stretch it begins is not the cache's, and a Turn begun for a Compaction, manual or scheduled, is its stretch's attempt whatever its own output does to the moment. It is skipped where the Session's Agent Selection differs in anything from the one the Turn that wrote the cache ran under — its Provider, its Model, or any Model Option, since a change of effort, thinking, speed or Routing Tier can leave the cache unread — or where that cannot be told, since the summary would then read the whole context at fresh prices, a routing Selection being judged as itself rather than by the Model its calls ran on; where the Cache Lifetime is no longer than the lead, since it would fall due as each Turn settled; and where less than twenty seconds of the cache's life is left when it comes to begin, since it would reach the Provider cold.

A Continuation, a Subagent Report reaching an idle Agent, or a Watch waking it is real work that writes the cache, so each begins a stretch of its own. A Session other Sessions wake can therefore be compacted once after each wake, with no Prompt from the user between.

## Considered Options

- **Widen "manual" to cover it.** Rejected: the Transcript would say the user asked for something they did not, and the two differ in what a held Prompt is owed (below).
- **Keep the cache warm with a periodic ping instead.** Rejected: it preserves the Agent's memory but pays a warm read of the whole context every Cache Lifetime for as long as the Session sits, where a Compaction pays once.
- **Gate on a minimum Context Fill**, as t3-code does at 200,000 tokens. Rejected for the dollar threshold: the same fill costs very different amounts on different Models.
- **Fire only on a Cache Lifetime the Provider reported.** Rejected: a lifetime Suru assumes drives the scheduled Compaction as it drives the warning, since the only Provider with nothing to go on is one whose cache does not lapse at all.
- **Keep the timer only in the Session's Provider actor.** Rejected: no actor runs for a tree evicted for going unused, nor for a Session a restarted Server has yet to be asked about, so a scheduled Compaction would fire only while a client held the Session open, the opposite of the case it exists for: an hour-long cache on a Session the user walked away from.
- **Start an actor at Server start for every Session whose lapse is still ahead, and keep it until then.** Rejected: it holds an actor, and with it the tree, for as long as a Cache Lifetime, which eviction (ADR 0022) exists to free.
- **Store which stretches were skipped.** Rejected as unneeded: a stretch is only ever judged once its moment has come, and one first found after its moment is skipped, so a restarted Server finds every stretch judged before it past due and skips it again. Two holes are accepted. A wall clock set back across a restart, past a moment already judged, finds that moment ahead again, and the stretch is judged a second time. And a lapse moment that moves later after the judgement — Copilot reporting a lapse outside any Turn moves it without beginning a stretch — can leave a restarted Server finding a skipped stretch not yet due; its cache is then really warm for that long, so the Compaction a second judgement may begin still reads it cheaply.

## Consequences

A scheduled Compaction may find its Session's Provider process already stopped, since ADR 0058 stops an idle Claude or Codex process after ten minutes and a Cache Lifetime can be an hour. It starts the process again, resuming the conversation from its stored Resume State as the next Turn would, rather than holding it alive until then: ADR 0058 exists to free those processes, and the Prompt Cache lives with the Provider, not the process. A process that fails to start fails the Compaction's Turn like any failed attempt, not tried again, and a Prompt held behind it is delivered all the same. The Compaction's Turn is the process's input like any other, so it is stopped for idleness again once that Turn has settled and waited idle. A pending scheduled Compaction is no work held, so it keeps neither the process nor the tree from being freed.

A Prompt sent to steer while a scheduled Compaction runs is held, as ADR 0041 holds one behind a manual Compaction, but it is delivered to begin the next Turn whether the Compaction completes or fails. ADR 0041 withdraws it when a manual Compaction fails because its writer expected a compacted context; nobody expected this one. An interrupt that reaches the Turn withdraws the Prompt unless the Compaction completes all the same, whether or not the interrupt stopped anything — it may find the Compaction already failed, or a Provider that cannot be asked to stop — because someone who pressed interrupt should not watch Suru begin a Turn with a Prompt held behind it. Its text returns to its writer, as ADR 0041 has it, and not to the client that interrupted. A Sidekick that wrote it has no composer to return it to, and is told nothing of the withdrawal, as of any Prompt of its own that no Turn took. Suru stopping mid-Compaction withdraws the Prompt as well, as it withdraws any Prompt still owed a Turn (ADR 0022): the Prompt is stored withdrawn, saying behind which Compaction, and its text is recovered only by a client still holding it.

A Session's lapse moment is stored, so a restarted Server still knows which Sessions are cold and which scheduled Compactions are still ahead of it. A stretch first found after its moment is skipped: a Server restarted after a moment passed attempts nothing for it, however long it was down. A stretch already found before a laptop slept through its moment, or before the wall clock jumped past it, is judged within a minute of the machine waking or the clock jumping, when its timer next reads the time, and begins only while the twenty-second margin of the cache's life remains: such a Compaction may begin late, but never into a cache gone or going.

The Session's actor keeps the timer for its scheduled Compaction while it runs, but the Server keeps one as well, for every Session, so a scheduled Compaction still fires on time where no actor runs: its tree evicted with no client attached, or the Server restarted since it was armed. Whether a stretch is owed one and when it falls due is read from the stored lapse moment and the Session's Turns, which a Server holds for every stored Session from its start without reading any history in, so starting commits and publishes nothing for Sessions nobody has opened.

A minute before the moment, where no actor runs and the Setting, the Provider and the Session's standing would let it begin, the Server reads the Session's tree back in and starts its actor, which judges the Compaction when it falls due exactly as it would have, under the same bounds. That read-in is the one access to a stored Session nobody asked for, and does what any first access does (ADR 0022): a Turn a stop left open settles and a stranded Prompt withdraws, as they would for the first client to open it. A tree read in so is held only as any tree is, by its use: evicted again before the moment, it is read in once more at the moment, and not again for that stretch: if still no actor judges it then, the stretch is skipped. Whatever is judged at the moment without the history — the Setting off, the Provider unable, a Settled Session under "active only" — skips the stretch where it lies, with nothing read in.

Which stretches have been judged is held in memory alone, and a skip outlives a restart all the same, as the considered options say. A stretch that had its attempt is told by its latest Turn being its Compaction's, a Turn a stopping Server left open included; and a Turn a stop left open writes nothing to the cache as it settles, since no process saw its output land, so the stretch it ends is never owed one. That errs towards skipping: such a Turn may have written the cache before the stop, but its moment is not known.

A pending scheduled Compaction is published with the Session, as the moment it falls due, wherever Suru would begin it then as things stand, with or without an actor running: it is the judgement made at the moment, made ahead of it, and is withdrawn as soon as anything rules it out — a Prompt, work in the tree, a Setting, a Settle, a changed selection, a penalty short of the minimum — so a Session the moment would skip shows nothing pending, and one skipped at its moment is never shown pending again. Like the Lapse Penalty it is derived and never stored, and a Session nobody has opened has nothing committed or broadcast for it: one read back in has it judged as it is read. A client counts it down above the composer in place of the lapse's countdown, from two minutes before the moment: that window is the client's own, as the lapse countdown's last minute is, and says nothing of the lead the Server falls due by. The client judges how long is left by its own clock, as it judges the lapse, and draws the line whatever the penalty, since the $0.05 floor keeps the warning of a lapse from nagging, and this line warns of nothing the user did not ask for.

The Lapse Penalty the judgement needs is forecast afresh when the Session is read back in, never stored. A Provider whose prices are known only once it has listed its Models (Claude, Copilot) could leave a restarted Server with no penalty to judge by, so before reading a Session in for its Compaction the Server has each enabled Provider list its Models, as a client connecting does. Where the prices are still not to hand at the moment, the stretch is skipped, and stays skipped once they come.

The Turn records Usage and Cost like any other, so what Suru spent compacting unasked is visible in the Session's Cost and in Usage Metrics.
